# ショートカット起動検索モーダル 設計書

作成日: 2026-06-27

## 目的

現行の「デスクトップ上に常駐アイコンを表示し、マウスオーバー/クリックで一覧を出す」方式を廃止し、グローバルショートカットからだけ呼び出す検索モーダル型ランチャーへ変更する。

登録済みフォルダを開くという中核機能、設定ファイルの互換性、エディタ起動コマンド、WSL パス対応は維持する。

## 現状

- `MainForm` が常駐アイコンの表示、ドラッグ移動、右クリック設定メニュー、ホバー監視、ホットキー処理を担当している。
- `FanPopup` がアイコン下の一覧パネルを per-pixel alpha のレイヤードウィンドウとして描画している。
- `Ctrl+Alt+Z` で `FanPopup` を表示/非表示できる。
- 一覧は `AppConfig.Entries` を `PathEntry.ByName` の昇順で表示する。
- 行クリックで `Launcher.Open` を呼び出す。
- 行右クリックで `EntryDialog` を開く。
- アイコン右クリックで `ManageDialog`、エディタ切替、最前面設定、終了を提供している。

## 変更後の体験

1. アプリ起動後、画面上に常駐アイコンは表示しない。
2. `Ctrl+Alt+Z` で画面中央に検索モーダルを表示する。
3. モーダル上部に検索用の文字入力欄を置く。
4. 文字入力欄の右側に「設定」「新規追加」ボタンを置く。
5. 入力文字列で登録パス候補を部分一致フィルタする。
6. 候補一覧の先頭行を標準選択する。
7. `↑` / `↓` で候補選択を移動する。
8. 候補選択中に `Enter` でその候補を開く。
9. `Tab` で入力欄、「設定」、「新規追加」へフォーカス移動できる。
10. 「設定」または「新規追加」にフォーカスがある状態で `Enter` を押すと実行する。
11. `Esc` または再度 `Ctrl+Alt+Z` でモーダルを閉じる。

## 非目標

- `settings.json` のスキーマ変更はしない。
- 登録パスの手動並べ替えは追加しない。
- エディタ起動コマンドの形は変えない。
- WSL 既定ディストリ解決の非同期化は今回の必須範囲に含めない。
- `EntryDialog` / `ManageDialog` の大幅な再設計は行わない。

## UI 詳細

### レイアウト

モーダルはプライマリ画面ではなく、現在カーソルがあるスクリーンまたはアクティブスクリーンの作業領域中央に表示する。

推奨サイズ:

- 幅: 640px 程度、DPI に応じてスケール
- 高さ: 最大 520px 程度
- 候補が少ない場合も検索欄と数行分の余白は維持
- 候補が多い場合は一覧だけスクロール

構成:

```text
+------------------------------------------------+
| [検索入力................................] [設定] [新規追加] |
|------------------------------------------------|
| > WSL : github - open-folder                   |
|   C : work - sample                            |
|   ...                                          |
+------------------------------------------------+
```

### 検索

部分一致対象:

- `PathEntry.Name`
- `PathEntry.Path`
- `PathEntry.WslDistro` は任意。実装コストが低ければ対象に含める。

比較ルール:

- 大文字小文字は無視する。
- 全角/半角、かな正規化までは行わない。
- 入力が空の場合は全件表示する。
- 表示順は常に既存契約どおり `PathEntry.ByName` の昇順を維持する。

### 選択

- フィルタ結果が 1 件以上ある場合、先頭を自動選択する。
- 検索文字列変更後は先頭を選択する。
- `↓` は次の候補、`↑` は前の候補へ移動する。
- 端でさらに移動した場合は折り返す。
- 候補が 0 件の場合、選択インデックスは `-1` とし、`Enter` では何もしない。

### キーボード

検索入力欄フォーカス時:

- 通常文字入力: 検索文字列を更新
- `↑` / `↓`: 候補選択を移動し、入力欄フォーカスは維持
- `Enter`: 選択中候補を開く
- `Tab`: 「設定」ボタンへ移動
- `Shift+Tab`: 通常の逆順移動
- `Esc`: モーダルを閉じる

ボタンフォーカス時:

- `Enter` / `Space`: ボタンを実行
- `Tab`: 次のフォーカス先へ移動
- `Esc`: モーダルを閉じる

候補一覧:

- マウスクリックでも候補を開けるようにする。
- 候補一覧自体は Tab 停止させない方針。キーボード操作は検索入力欄から完結させる。
- ダブルクリック必須にはしない。クリックで即起動する現行体験を保つ。

## ウィンドウ/フォーカス仕様

### 常駐本体

`MainForm` は画面上に見せないホットキー受け取り用ウィンドウに役割を縮小する。

候補:

- `MainForm` を `ShowInTaskbar = false`、`Opacity = 0`、最小サイズにして不可視化する。
- または `NativeWindow` ベースのメッセージ専用クラスへ置き換える。

推奨は段階的移行しやすい前者。

ただし、現行のアイコン描画、ドラッグ移動、ホバー監視、位置保存は削除対象になる。

### モーダル

新規 `LauncherDialog` を追加する。

- `FormBorderStyle = FixedSingle` または `None` + 独自描画のどちらでもよい。
- まずは通常 WinForms コントロール中心で実装し、アクセシビリティとキー操作を安定させる。
- `StartPosition = Manual` で中央配置する。
- `ShowDialog(owner)` ではなく `Show(owner)` を基本にする。グローバルホットキーから再トグルしやすくし、アプリ全体を固めすぎないため。
- ただし利用者体験としては「モーダル相当」に見せるため、表示中は前面に出し、検索欄にフォーカスする。
- `TopMost` は既存 `AlwaysOnTop` 設定を適用する。

### ホットキー

- 既存の `Ctrl+Alt+Z` を維持する。
- モーダル非表示時: 表示
- モーダル表示時: 閉じる
- モーダル表示直後は検索入力欄を空にして全件表示する。

## 設定/追加フロー

### 設定

「設定」ボタンは既存の設定メニュー相当を開く。

初期実装では `ContextMenuStrip` をボタン下に表示するのが最小変更。

メニュー項目:

- パスの管理...
- エディタ: VS Code / Cursor / Antigravity
- 常に手前に表示
- 終了

`ManageDialog` から戻ったら設定を保存し、検索モーダルの候補一覧を再読み込みする。

### 新規追加

「新規追加」ボタンは `EntryDialog` を直接開く。

OK の場合:

- `AppConfig.Entries` に追加
- `PathEntry.ByName` でソート
- `AppConfig.Save()`
- 検索結果を再構築
- 追加したエントリが現在の検索語に一致するなら、その行を選択
- 一致しない場合は検索語を空にして追加したエントリを選択する案が自然

## 実装方針

### 追加/変更ファイル

- `source/MainForm.cs`
  - ホットキー登録/解除とモーダル表示管理に縮小する。
  - アイコン描画、マウス操作、ホバー監視、位置保存を削除する。
- `source/LauncherDialog.cs`
  - 検索入力、設定ボタン、新規追加ボタン、候補一覧、キーボード操作を実装する。
- `source/FanPopup.cs`
  - 使わなくなる。削除するか、移行期間は未参照のまま残す。
  - 削除する場合は `Draw.RoundedRect` を使う箇所が残るか確認する。
- `README.md`
  - 利用者向け操作説明をショートカット起動検索モーダルへ更新する。
- `AGENTS.md`
  - コード構造が変わるため、実装時に必ず更新する。
- `tests`
  - 検索フィルタを純粋関数化できる場合はテストを追加する。

### 推奨クラス分割

検索ロジックを UI から切り出す。

候補:

- `EntrySearch`
  - `Filter(IEnumerable<PathEntry> entries, string query)`
  - 大文字小文字無視の部分一致
  - 昇順維持

これによりテストしやすくなる。

### `LauncherDialog` の内部状態

- `_config`
- `_allEntries`
- `_filteredEntries`
- `_selectedIndex`
- `_queryBox`
- `_settingsButton`
- `_addButton`
- `_list`

候補一覧は `ListBox` を使うのが最小実装。

- `DrawMode = OwnerDrawFixed` にすると、既存の `ChipTheme` 色を活かせる。
- 初期実装では標準描画でもよいが、視認性維持のため owner draw を推奨する。

## 既存契約への影響

維持するもの:

- `settings.json` の PascalCase スキーマ
- `Entries[]{ Name, Path, IsWsl, WslDistro, ChipTheme }`
- `Editor`, `AlwaysOnTop`
- `Launcher.Open` のコマンド形
- `Local\open-folder-widget` Mutex 名
- 登録パスの名前昇順
- `ChipTheme` 旧エイリアス受理

変更/廃止するもの:

- デスクトップ常駐アイコン
- アイコン位置保存 `WindowX` / `WindowY` の使用
- マウスオーバーでの表示
- アイコンドラッグ移動
- アイコン右クリックメニュー
- 行右クリックで編集
- `FanPopup` のスライド/フェード表示

`WindowX` / `WindowY` は後方互換のため settings.json から削除しない。読み書きは残してもよいが、今後は使用しない。

## テスト観点

### 自動テスト

- 空文字検索で全件が名前昇順に返る。
- 名前の部分一致で絞り込める。
- パスの部分一致で絞り込める。
- 大文字小文字を無視する。
- 一致なしの場合は 0 件になる。

### 手動確認

- 起動してもアイコンが表示されない。
- `Ctrl+Alt+Z` で中央にモーダルが出る。
- 再度 `Ctrl+Alt+Z` で閉じる。
- 表示直後に検索欄へフォーカスがある。
- 入力で候補が絞られる。
- 先頭候補が選択される。
- `↑` / `↓` で選択が移動する。
- `Enter` で選択候補が開く。
- `Tab` で「設定」「新規追加」に移動できる。
- ボタンフォーカス中に `Enter` で実行できる。
- `Esc` で閉じる。
- 「新規追加」後に候補一覧が更新される。
- 「設定」からエディタ切替、パス管理、終了ができる。
- WSL パスが従来どおり開ける。
- publish 版を `restart.ps1` で入れ替えても多重起動しない。

## 実装ステップ案

1. 検索ロジックを純粋関数として追加し、テストを追加する。
2. `LauncherDialog` を通常 WinForms コントロールで新規作成する。
3. `MainForm` をホットキー受け取りと `LauncherDialog` 表示管理に縮小する。
4. 設定/新規追加フローを接続する。
5. `README.md` と `AGENTS.md` を更新する。
6. `dotnet build` と `dotnet run --project tests` を実行する。
7. `restart.ps1` で publish 版を再起動し、手動確認する。
